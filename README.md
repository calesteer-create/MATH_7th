# MATH 7TH — رياضيات الصف السابع

منصّة تعليمية عربية لدراسة رياضيات الصف السابع وفق **المنهاج السوري**: دروس مصوّرة من الكتاب المدرسي يرفعها مالك المنصّة، واختبار لكل درس واختبار شامل لكل وحدة.

> **ملاحظة أساسية:** المستودع لا يحتوي على أي محتوى رياضيات. جميع الدروس والصور يضيفها مالك المنصّة من لوحة الإدارة. لا يوجد في الكود أي شرح أو تمرين أو وحدة مختلَقة.

### مسودات الإدارة والصور (PR 5)

```bash
npm run admin:config            # يولّد public/admin/config.yml (الوجهة مثبتة، لا تحرّره يدويًا)
npm run media:import -- --lesson 3 --from ~/scans/lesson-3   # WebP + بلا EXIF/GPS
npm run media:sync              # يكمّل ما يرفعه المتصفح: sha256، الأبعاد، المصغّرات
npm run admin:verify-github     # يتحقق من مستودع المسودات الخاص (أنت تشغّله)
```

> ⚠️ تكامل Sveltia مع مستودع GitHub **الخاص** لم يُتحقَّق منه بعد. لا تعتمد على
> `/admin/` لحفظ محتوى حقيقي قبل تنفيذ خطوات [docs/ADMIN.md §5](docs/ADMIN.md).
> وجهة المسودات مثبتة في `calesteer-create/MATH_7th-drafts`: `DRAFT_REPO` لا
> يستطيع تحويل اللوحة إلى مستودع آخر (اسم المستودع ليس دليلًا على أنه خاص).

### متغيرات البيئة

| المتغير | الوصف |
|---|---|
| `ADMIN_SESSION_SECRET` | سرّ توقيع جلسة الإدارة (32 حرفًا فأكثر). ولّده بـ: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `ADMIN_USERNAME` | اسم مستخدم المالك (الافتراضي `owner`) |
| `ADMIN_PASSWORD` | كلمة مرور المالك — 10 أحرف فأقل لن تُقبل |
| `TIME_ZONE` | المنطقة الزمنية للعرض (الافتراضي `Asia/Damascus`) |
| `UPLOAD_DIR` | مجلد الصور (الافتراضي `./data/uploads`) |
| `MAX_UPLOAD_BYTES` | الحد الأقصى لحجم الصورة (الافتراضي 15 ميغابايت) |
| `QUIZ_PROVIDER` `QUIZ_API_KEY` `QUIZ_MODEL` `QUIZ_API_BASE_URL` `QUIZ_VISION_MODEL` | خدمة توليد الاختبارات — تُقرأ في الخادم فقط، ولا تصل إلى المتصفح أبدًا |

**المنصّة تعمل بالكامل دون ضبط خدمة التوليد**؛ تظهر فقط رسالة في لوحة الإدارة بأن التوليد متوقف.

## البنية التقنية

| الطبقة | الاختيار | السبب |
|---|---|---|
| الإطار | Next.js 16 (App Router) + React 19 + TypeScript 7 | عرض من الخادم لصفحات ثقيلة بالصور على أجهزة متواضعة، وقابل واحد للنشر |
| قاعدة البيانات | SQLite عبر `better-sqlite3` + Drizzle ORM | مشروع شخصي بمالك واحد: ملف واحد، ونسخة احتياطية بنسخ الملف، وبلا خادم قاعدة بيانات |
| الترجمة | next-intl (`ar` افتراضيًا، `en`) | كتالوج رسائل مكتوب الأنواع، واكتشاف المفاتيح الناقصة |
| التنسيق | Tailwind CSS 4 + خصائص منطقية | `ms-/me-/ps-/pe-` تجعل الاتجاه محايدًا في كود واحد |
| الخط | Readex Pro Variable (مستضاف ذاتيًا) | عائلة واحدة تغطي العربية واللاتينية، فلا يتبدّل الخط عند تغيير اللغة |
| الصور | sharp | تصحيح الدوران، حذف EXIF (بما فيه GPS)، وإنتاج نسخ WebP |
| كلمة المرور | `scrypt` من `node:crypto` | بلا تبعية خارجية، ومقاوم للذاكرة |
| الجلسة | كوكي موقّع بـ HMAC، `HttpOnly` + `SameSite=Lax` | قابل للإبطال فورًا، وبلا مكتبة مصادقة |

### لماذا SQLite وليس PostgreSQL؟

لأن المشروع شخصي بمالك واحد ولا يحتاج وصولًا متزامنًا كثيفًا. SQLite يلغي خادم قاعدة بيانات كاملًا من التشغيل والنسخ الاحتياطي. الطبقة معرّفة عبر Drizzle، فالانتقال إلى PostgreSQL لاحقًا لا يمسّ منطق التطبيق.

### قرارات تقنية تستحق الذكر

- **لا ESLint**: حزمة `typescript-eslint` التي تعتمد عليها `eslint-config-next` لا تدعم TypeScript 7، فالإعداد يفشل عند التحميل. بدل إضافة حزم، القاعدتان اللتان تحميان هذا المنتج تحديدًا (الاتجاه المنطقي، والأرقام الغربية) مطبَّقتان في `scripts/guard.mjs` — بلا تبعيات تتقادم، ومُختبَرتان ضد مخالفات متعمَّدة. فحص الأنواع يقوم به `tsc --strict`.
- **لا `drizzle-kit`**: ملفات الترحيل SQL مكتوبة يدويًا في `src/db/migrations/`، ويؤكّد `tests/schema.test.ts` أنها مطابقة لمخطط Drizzle فلا يحدث انحراف.
- **لا SDK للذكاء الاصطناعي**: نداء `fetch` واحد إلى واجهة متوافقة مع OpenAI، فيمكن تغيير المزوّد بمتغيرات بيئة فقط.
- **التخزين على القرص**: بلا خدمة تخزين سحابي في الإصدار الأول؛ الصور في `data/uploads` ولا تُخدَم إلا عبر مسار يفحص الصلاحية.
- **الدخول عبر مسار API قياسي** (`/api/admin/login`) لا Server Action، حتى يكون تدفّق المصادقة قابلًا للاختبار خارج المتصفح.
- **بناء واحد بوضعين** (PR 4): ملفات المسارات التي تحتاج خادمًا تحمل لاحقة `.srv` ويحدّد `pageExtensions` أيها يُبنى في كل وضع، والصفحات العامة تستدعي `renderPerRequest()` فتُعرض حيًّا على الخادم (سلوك لم يتغيّر) وتُثبَّت مرة واحدة عند تصدير GitHub Pages — التفاصيل في [docs/STATIC_EXPORT.md](docs/STATIC_EXPORT.md).

## القواعد التي يحرسها الكود

1. **الأرقام الغربية إلزامية.** `src/lib/format.ts` يثبّت `numberingSystem: "latn"`، والحارس `npm run guard` يمنع `Intl.NumberFormat` و`toLocaleString` خارج هذا الملف. السبب: `ar-SY` يستخدم افتراضيًا الأرقام الشرقية `١٢٣٤٥٦٧٨٩`، بينما `ar` وحدها تستخدم الغربية — فلا يُعتمد على أي افتراضي.
2. **لا خصائص اتجاه فيزيائية.** `npm run guard` يفشل عند `ml-` أو `pr-` أو `text-left` أو `row-reverse` أو `style={{ left }}`؛ البديل `ms-/me-/ps-/pe-/start-/end-`.
3. **المحتوى العربي يحمل لغته دائمًا.** مكوّن `<Ar>` يضع `lang="ar" dir="rtl"` على كل عنوان أو وصف من محتوى المالك، حتى داخل الواجهة الإنجليزية، فلا تنطقه قارئات الشاشة حرفًا حرفًا.
4. **الصور خاصة.** لا وصول ثابتًا (static) إلى `data/uploads`؛ كل صورة تمرّ بفحص: المنشور عام، والمسودة للمالك وحده. مفاتيح التخزين لا تظهر في HTML.
5. **EXIF يُحذف عند الرفع**، لأن صور الهاتف تحمل إحداثيات GPS.
